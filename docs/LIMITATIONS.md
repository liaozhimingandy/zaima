# 已知问题与限制（V1）

本文件是「不能忽略的真相清单」。上线前请逐条确认。

---

## 1. V1 功能边界（有意不做）

- 无注册/登录、无短信验证、无第三方账号绑定
- 无远程 Push、无小程序订阅消息（微信/支付宝）
- 无 SOS、定位、健康数据、聊天、AI、付费会员
- 不会把「超时未确认」判定为死亡或事故
- 无账户删除、无数据导出接口

## 2. 产品行为说明（不是 Bug，但容易误解）

### 2.1 首次使用的应确认时间在 24 小时之后

首次以**账户创建时间**为锚点计算：`创建日 + 周期天数` 的本地设定时刻。

例：今天 05:48 安装、周期 1 天、时间 08:00 → 下次应确认 = **明天 08:00**（约 26 小时后），而不是今天 08:00。

设计原因：避免用户刚安装就被判超时、甚至直接给守护人发邮件。

### 2.2 关闭提醒后不出现 `REMINDING`

`remindersEnabled=false` 时，到期后状态保持 `PENDING` 直到异常阈值（默认 24 小时）。这是有意为之（没有提醒就不应显示"提醒中"）。

### 2.3 修改设置不会重算已存在的异常事件

如果账户已处于 `ALERT`（存在 open 事件），此时修改周期或确认时间：
- 事件仍以原 `due_at` 保留，直到用户点「我在」才会关闭
- 不会因为"新周期更长"而自动关闭旧事件

### 2.4 邮件正文在发送时渲染

`notification_record` 只存主题与收件人快照，正文在派发时用**当时的设置**重新渲染。若事件创建后用户改了周期，邮件里的「确认周期」是发送时刻的值。

### 2.5 事件创建后再新增的守护人不会收到本次邮件

通知任务在事件创建瞬间按当时的守护人列表生成。之后新增的守护人只对**下一次**事件生效（V1 简化，避免重复打扰）。

## 3. 安全与可靠性

| 问题 | 现状 | 建议 |
| --- | --- | --- |
| 接口无限流 | `/api/account/init` 可被批量调用创建账户 | 上线前在网关层加 IP 限流（如 10 次/分钟），或引入 Turnstile |
| 账户无找回 | 匿名设计使然，符合产品定位 | 已在 App 内首次启动弹窗与设置页明示 |
| 凭证泄漏风险 | 凭证存于客户端本地存储，H5 下可被同源脚本读取 | 生产 csp 加固；不要引入不可信第三方脚本 |
| 凭证轮换 | 不支持 | 后续可加「迁移账户」流程 |
| 邮件被判定为垃圾邮件 | 未配置 SPF/DKIM/DMARC | 生产必须配置域名邮件认证 |
| 单点调度 | 依靠 advisory lock 保证同一时刻只有一个实例扫描 | 多副本部署时仅一个开启 Scheduler |
| 无审计日志表 | 调度结果只写结构化日志，不落库 | 需要时可加 `job_run` 表 |

## 4. 前端

| 问题 | 说明 |
| --- | --- |
| 时区选择 | 设置页只展示时区，未提供手动切换。初始化时上报设备时区；若用户换时区，需要重装或后续版本支持 |
| 自定义 TabBar | 未使用原生 tabBar（避免多端图标差异），切换用 `uni.reLaunch`，页面会重建（状态从服务端拉取，无副作用） |
| 倒计时精度 | 以服务端 `serverTime` 修正本机时钟，每秒本地刷新；阶段仍以服务端返回为准，页面停留时每 60 秒静默同步一次 |
| 系统通知 | H5 需用户授权，App 依赖 `plus.push`（可能被系统省电策略拦截），小程序不支持。**页面内提醒是唯一始终可用的通道** |
| 真机未验证 | 小程序/App 未在真机运行，布局与安全区适配需在目标设备复核 |

## 6. 已知小问题（不影响闭环）

1. `GET /api/checkin/settings` 返回的 `reminders[].passed` 恒为 `false`（该接口只描述"规则"，实时进度请看 `/checkin/status`）。
2. 历史记录接口无「总条数」，前端只展示「加载更多 / 没有更多了」。
3. H5 首次启动弹窗（账户不可找回提示）只在未确认过时出现，清除缓存后会再次出现。
4. 删除守护人后，其历史通知记录保留（`guardian_id` 置 NULL），属预期行为。
